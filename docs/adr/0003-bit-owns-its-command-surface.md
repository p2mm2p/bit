# 命令面自成一格：bit 的用法层退出码与 git 不共用

bit 只有两个命令、没有任何透传，于是「怎么被调用」这件事全由 bit 自己定义，不必向 git 的选项解析器看齐。退出码分三层：**用法层失败**（没有指定命令、未知命令、未知选项、多余参数）= **2**、诊断到 stderr；**运行期失败**（Esc 取消、非 TTY、无暂存内容、编辑器非零退出）= **1**；**git 自身的失败**（重名、非法 ref、非仓库）= git 的退出码**原样透传**（128 等）。帮助与版本的「请求」（`-h` / `--help` / `-V` / `--version`）是唯一走 stdout 且退出码 0 的输出。文案全部中文（bit 自产），git 的 stdout/stderr 一字不改——两者叠加，任何一行输出都能判出「谁在说话」。

## Considered Options

- **对齐 git**（无参数 → usage 到 stdout + 1；坏选项 → 129）（否）：129 是 git 自己选项解析器的码，bit 没有可对齐的解析器；两套码并存只会让「这是谁的失败」变模糊，而照搬还会把「没给参数」错当成运行期失败。
- **无参数按 cargo / gh 处理**（help 到 stdout + 0）（否）：`bit` 无参数没有任何默认动作可做——报 0 等于告诉脚本「它做完了」。这不是「请求帮助」，而是「没说要做什么」，属用法错误。
- **只留 0 与 1，不引入 2**（否）：用户反悔（取消）与命令写错（调用方式不对）挤进同一个码，脚本与习惯都无从区分；#4 / #7 已把 1 定义成「bit 开始做事之后的失败」。

## Consequences

- 「谁的失败」一眼可判：**2 = 用法层（还没开始做事）、1 = 运行期（开始后失败或被取消）、128+ = git 说的**（原样透传，不翻译、不包装）。
- 帮助请求走 stdout、诊断一律走 stderr：`bit --help | less` 干净，重定向 stdout 不会把诊断混进去或吞掉。
- 未被枚举的输入（`--`、组合短选项、任何多余位置参数）不逐条特判，统一落进用法错误出口。
- bit 的每一句话都是中文、git 的每一句话都是英文原文（`fatal:` / `error:`）——语言本身成了来源标记。
- 不做 locale 开关：v0.1 只服务本机；文案模板冻结在 [命令面 · 帮助、错误与文案语言](https://github.com/p2mm2p/bit/issues/8)，实现直接抄。
- 交互界面渲染到 stderr（inquire 的现状），stdout 只承载 git 的输出——管道的消费者拿到的仍是纯 git 语义。

决定过程与实测证据（git 2.55.0.windows.5、cargo 1.98.1、gh 2.98.0）见 [命令面 · 帮助、错误与文案语言](https://github.com/p2mm2p/bit/issues/8)。
